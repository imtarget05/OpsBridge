## Immediate Phase 1 order

1. Resolve production IdP and staff role mapping. The mock Google path has been removed from the web source; a production sign-in journey still needs implementation and UAT.
2. Fix connector ping at the API and UI. A health check and a literal success response cannot substantiate connectivity.
3. Define the cross-context contract and threshold for stuck-order detection before writing a detector.
4. Run current CI/local tests, then collect cloud evidence from the exact release SHA. Prior run counts in `README.md`, `traceability-matrix.md` and `gap-register.md` are historical.

Owner and independent UAT sign-off remain unassigned. The forecast scope decision and IdP choice are open; no official MVP or full-scope percentage should be calculated from this document yet.

### Same-day implementation note — US-C-07 / FR-C04

The row above records the baseline before implementation. A later local change added FlashSale-owned detection of an accepted `inventory.reserved` event that has no Order row after a configurable threshold, with a worker scan and admin-only API. See [accepted-order stall detection](../architecture/stuck-order-detection.md). This is narrower than post-payment shipment tracking and does not turn the historical outbox-publication `/api/outbox/stuck` endpoint into an order-stall detector. Unit/integration test source was added, but runtime tests and cloud fault evidence are still pending; the requirement remains **partial**, not accepted.
